# translations/ — localization data (en / ja)

Registered in project.godot `[internationalization]`; runtime helper:
`Loc.t(key)` (`scripts/localization/`).

## Contents

| Item | What it is |
|---|---|
| `strings.csv` | UI + game-log strings (`STR_*`, `STR_LOG_*`), header `keys,en,ja` |
| `cards.csv` | Per-card text: `CARD_<id>_NAME` / `CARD_<id>_DESC` — **generated**, don't hand-edit |
| `*.translation` (+ `.import`) | Godot-compiled binaries the engine actually loads (regenerated by the editor when a CSV reimports) |
| `en_sources/`, `ja_sources/` | Scraped per-set card-effect text files (`bp01_card_effects_ja.txt`, …) that feed the generator |
| `generate_card_csv.py` | Regenerates `cards.csv` |

## Workflow

```
scripts/cards/card_data.gd  ─┐
                             ├─→ python3 translations/generate_card_csv.py ─→ cards.csv
ja_sources/*_card_effects_ja.txt ─┘
strings.csv  (hand-edited)
        └─ both CSVs → Godot editor reimport → *.translation → shipped
```

- **Adding a UI/log string:** add the `STR_*` row to `strings.csv` (en + ja),
  reference it via `tr()` / `Loc.t()`. Game-log events also need a token
  constructor in `scripts/replay/game_log.gd`.
- **Adding/changing card text:** edit the card in
  `scripts/cards/card_data.gd` (and JP source file if applicable), then run
  `python3 translations/generate_card_csv.py` (it regex-parses card_data.gd —
  update `CARD_DATA_GD` there if the database file layout changes).
- ID mapping: English `EBP01-001` ↔ JP `BP01-001`; the generator prefers
  non-`+` reprint variants.
- Open the project in the editor once after regenerating so the CSVs
  recompile to `.translation`.

Caveat: multiplayer JSON turns int enums into floats — card text keys are
strings, but deck-search picks etc. must re-map by id (see
`scripts/cards/README.md`).
