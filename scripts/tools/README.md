# scripts/tools/ — dev & CI check scripts

Not shipped features — run these during development.

The `check_*.py` ratchets share `gd_ratchet.py`: allow-list keys are
`<file>: <code>` (no line numbers), one line per occurrence, and a check
fails on a NEW hit and on a STALE allow-list line, so the lists only shrink.
`--update` rewrites a list from the tree; additions need a reason in the PR.

`run_checks.sh` runs every mechanical check below in one go; it is the one
list `githooks/pre-commit` (`--staged`: only checks whose files are staged)
and `tests.yml` call. Wire a new check by adding a row to its `CHECKS`
table — "Runs in CI and the pre-commit hook" below means "is in that table".

| `check_designer_contract.gd` | A GameBoard scene satisfies the multiplayer scene contract: root named `GameBoard`, `GameSession` child containing `MultiplayerSync` (required) + `EffectUIRouter` (warning if absent). Exit 0 = pass. | `<godot> --headless --quit --script scripts/tools/check_designer_contract.gd -- res://scenes/board/GameBoard.tscn` (or `-- --all` to scan `scenes/board/`) |
| `check_engine_private_calls.py` | Ratchet: no new `x._method(` calls into private methods defined in `scripts/core/` or `scripts/effects/` from other files (call a public engine method instead). | `check_effect_handler_card_api.py` | Ratchet + guards: `EffectHandler` is exactly the card-script interface. (1) Every public `EffectHandler` method has a caller in a per-card script (`scripts/effects/<set>/`) through a handler receiver — `effect_handler.` / `EffectHandler.`, or a file-local alias typed `: EffectHandler` or assigned `= ctx.effect_handler`; a same-named method on another object doesn't count. Lifecycle `setup` / `teardown` are exempt; pending removals live in `effect_handler_card_api_allowlist.txt` (empty). (2) Card scripts never reach a module behind the facade (`ctx.effect_handler.queries.…`); no allow-list. (3) Every `effect_handler.<name>` / `["effect_handler"].<name>` under scripts/ scenes/ tests/ names a real EffectHandler member — through an untyped receiver a removed or misspelled method compiles and only fails when the line runs; no allow-list. Engine, core, UI, bot and tests call the modules (`effect_handler.queries` / `.dispatcher` / `.check_timing` / …). Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_effect_handler_card_api.py` |
| `check_card_monster_zone_checks.py` | Ratchet: per-card scripts (`scripts/effects/<set>/`) don't compare a zone index to the monster's zone index (`monster_zone - 1` or a variable assigned from it) — play-zone legality (5.11.1.1) belongs to the engine. Literal zone-number conditions (`monster_zone == 8`) aren't flagged. Grandfathered occurrences live in `card_monster_zone_checks_allowlist.txt`. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_card_monster_zone_checks.py` |
| `check_card_mutations.py` | Two scopes. (1) Guard, per-card scripts (`scripts/effects/<set>/`): they mutate state only through EffectHandler primitives. No zone / monster-position mutation (`clear_zone(`, `push_zone_card(`, `banish_or_discard(`, `monster_zone` assignment, `zones[...]` writes), no writes to `hand` / `discard_pile` / `main_deck` / `monster_deck` / `strategy_zones` (reassignment, index assignment, mutating Array method, also through a local alias), no PlayerState change-signal emits (`hand_changed.emit(`, …), and no `ctx.owner.` / `ctx.opponent.` call to a method in `scripts/core/player_state.gd` § Mutators (the list is read from that section, so new mutators are covered; `draw_cards` / `mill_cards` sit outside it and stay allowed — whole-rule operations with their own reshuffle, no EffectHandler draw primitive) (hunterdurbin/godzilla-sim-issue-tracker#30). Reads are fine. No allow-list. (2) Ratchet, engine (`scripts/core/**` + `scripts/effects/*.gd`, minus `player_state.gd`): the engine changes a player's areas only through PlayerState mutators, each of which emits its `*_changed` signal immediately (hunterdurbin/godzilla-sim-issue-tracker#23). Flags writes to those collections plus `monster_stack` / `strategy_zone_stacks`, `zones[...]` writes, `rage` / `current_monster` assignment, and change-signal emits. Grandfathered hits live in `engine_player_state_writes_allowlist.txt` (empty). Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_card_mutations.py [--update]` |
| `check_effect_resolution_notes.py` | Guard: every engine site (`scripts/effects/*.gd`) that awaits a card hook (`effect.on_*(` / `apply_*(` / standby `callback.call()`) calls `note_effect_resolving` just before — it feeds `GameEvents.effect_resolving`, i.e. the bot sim's `[SimEffects]` counts and `run_sim_diff.sh`'s UNEXERCISED verdict. Lambda bodies (standby callbacks, announced by the resolver) and sync replacement hooks are exempt. No allow-list. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_effect_resolution_notes.py` |
| `check_card_unawaited_coroutines.py` | Guard: per-card scripts call every engine coroutine with `await` (an un-awaited call returns immediately, so the card runs on mid-move). The coroutine set is derived from `effect_handler.gd` / `effect_context.gd` (functions containing `await`). No allow-list. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_card_unawaited_coroutines.py` |
| `check_typed_array_dynamic_calls.py` | Guard: no array literal is passed to a method with an `Array[...]` parameter through a dynamic call (`x.method.bind(..., [2])` or `x[...].method(..., [2])`): it arrives untyped, the coroutine aborts and the awaiting caller (often a gdUnit test) hangs forever. Hoist a typed local, cast (`as Array[int]`) or call inside a lambda. No allow-list. Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_typed_array_dynamic_calls.py` |
| `check_player_input_contract.py` | Guard: every PlayerInput implementation (transitively, inner test classes included) overrides each base method with the same parameter types, defaults and return type as `scripts/core/input/player_input.gd` (a mismatch aborts the awaiting engine coroutine), and every handler connected to a `SignalPlayerInput` prompt signal (`.connect(name)`, `.connect(func(...)`, or the `[pin.<signal>, name]` map) takes that signal's argument count (Godot errors only when it fires — GameBoard handlers run in no test). `.bind(` connections skipped. No allow-list. Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_player_input_contract.py` |
| `check_standby_entry_builders.py` | Guard: no `StandbyEntry.new(` or `check_timing.submit(` under `scripts/` outside `scripts/effects/trigger_dispatcher.gd` — its private `_collect_*_entries` functions are the one place that applies TRIGGER_FILTERS, builds the context and attaches `still_applies` (10.6.3); operations call its `trigger_*` functions, which submit. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_standby_entry_builders.py` |

A fixed `ALLOWED` set in the script (state restore, bot planning, previews, the board editor) writes it outside play, each with its reason; tests may set it. Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_monster_zone_writers.py` |

| `check_docstring_signals.py` | Guard: no indented `##` docstring line in an engine module (`scripts/core/**`, `scripts/effects/*.gd`, minus `player_state.gd`) names a PlayerState `<area>_changed` signal. | `check_tracker_refs.py` | Guard: no bare tracker ref (`#N row M`, `tracker #N`) in `.gd` / `.py` / `.sh` / `.md` files under `scripts/`, `scenes/`, `tests/`, `githooks/`. Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_tracker_refs.py` |

Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_rank_up_rule_owner.py [--update]` |
| `check_log_message_tokens.py` | Guard: every `log_message.emit(` under `scripts/` or `scenes/` passes a `GameLog.` token (the argument may start on the next line). The signal is `(token: Dictionary)`: a host-translated String misses the typed listeners (ReplayRecorder, the bot sim's [SimEvents]) and shows the host's language to a client; tokens render per viewer via `GameLog.render` (hunterdurbin/godzilla-sim-issue-tracker#45). A new kind of line gets a GameLog builder + `render` case. No allow-list. Built-in pattern self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_log_message_tokens.py` |
| `check_pr_tracker_link.py` | Guard: the PR body closes its tracker issue (`Closes hunterdurbin/godzilla-sim-issue-tracker#N`, the only wording GitHub acts on across repos) or carries a `Tracker: none` line. Also warns (never fails) on each bare `#N` outside code (fences and inline spans): it links a code-repo PR, so a tracker ticket or decision row needs the full ref (a GitHub annotation in CI). Reads the body from `$PR_BODY` or stdin. Built-in pattern self-test. Runs in CI (`pr-tracker.yml`, re-run on body edits); not in pre-commit (no PR body there), so run it on the body file before `gh pr create`. | `python3 scripts/tools/check_pr_tracker_link.py < body.md` |
| `check_commit_msg_refs.py` | Warning, never blocks: a bare `#N` in a commit message (git comment lines skipped). Runs from `githooks/commit-msg` (install: `ln -s ../../githooks/commit-msg .git/hooks/commit-msg`). | `python3 scripts/tools/check_commit_msg_refs.py <msg-file>` |
| `check_gd_uid_pairs.py` | Guard: every tracked `.gd` has its `.gd.uid` tracked too (Godot 4 regenerates a missing one, which then sits untracked in every checkout and makes `git stash -u` refuse to pop). Dot-directories (`.claude/`) and `.gdignore` folders are exempt, since Godot never imports them. Built-in self-test. Runs in CI (`tests.yml`) and the pre-commit hook. | `python3 scripts/tools/check_gd_uid_pairs.py` |
| `check_gdscript_warnings.py` | Ratchet: no new GDScript compile warnings. Runs `dump_gdscript_warnings.gd` headless in debug mode (compiles every `.gd` under scripts/ scenes/ tests/, ~5 s) and keys each warning as `<file>: <message>`; grandfathered ones live in `gdscript_warnings_allowlist.txt`. Exempt: an unused `test_parameters` in tests/ (gdUnit4 needs that exact name). A SCRIPT ERROR in the dump fails it too. Runs in CI (`tests.yml`, after the unit suite) and the pre-commit hook when `GODOT_BIN` is set; `run_unit_tests.sh` also prints NEW warnings from its own log (`--log <file> --new-only`). | `python3 scripts/tools/check_gdscript_warnings.py <godot> [--update]` |
| `check_class_cache.py` | Is `.godot/global_script_class_cache.cfg` current with every `class_name` on disk (missing, moved or gone classes)? A stale cache makes headless runs fail with a misleading `Identifier "X" not declared`. `tests/run_unit_tests.sh` calls it and runs `tests/import.sh` when it fails (`tests/sim/run_sim_diff.sh` imports its own snapshot instead). Built-in pattern self-test. Not in pre-commit/CI (the cache is local state). | `python3 scripts/tools/check_class_cache.py [--quiet]` |
| `check_missing_cards.sh` | Diffs card ids in `scripts/cards/sets/card_set_*.gd` against the live API (`https://api.godzillatcg.com/cards`), reporting missing cards grouped by set. Needs `curl` + `python3`. | `./scripts/tools/check_missing_cards.sh` |
| `cards_with_hook.py` | Lookup, not a check: lists every card whose effect script overrides a CardEffect hook, with its description and the qa.txt Q-numbers that tag it. Use it before changing when a hook fires, or when a rules decision depends on the affected cards' wording. | `python3 scripts/tools/cards_with_hook.py <hook> [<hook> ...]` |
